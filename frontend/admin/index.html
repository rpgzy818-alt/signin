统计口径、排重规则与平台化说明

指标字典

Meeting · 数据统计口径 v1.0

一、访问量三兄弟

指标口径
页面 PV页面被浏览的次数。每次进入一个视图记 1 次，同一人刷新或重复进入会累加；800ms 内的重复渲染自动去重。
访客 UV统计周期内去重的访客人数，按匿名设备号 did 判定。同一设备当天来 10 次算 1 人；换设备、清缓存会算成 2 人。
识别用户其中已拿到微信身份（openid）的人数。授权前或非微信访客不进这一项，所以它一定 ≤ 访客 UV。
会话数一次连续访问算一个会话，同一会话内可浏览多个页面，用来算人均浏览深度。

⚠ 日 UV 不能直接相加成区间 UV：同一人每天都来，每日 UV 都是 1，30 天累计 UV 仍是 1。这是行业统一口径。

二、渠道归因

来源判定方式
渠道码扫码扫通用报名码或渠道码进来，链接带 from=material
分享链接微信分享出去的链接，带 from=share
活动链接直接打开的裸链接，无来源参数

系统同时记录「首次触点」和「本次触点」两份来源。默认按本次触点归因（看临门一脚），切到首次触点可看拉新贡献。同一个人换渠道再来，两种口径的结果必然不同。

三、设备识别

维度说明
设备大类分 iOS ／ 安卓 ／ 鸿蒙 ／ 其他。鸿蒙 UA 里含安卓标识，判定顺序是鸿蒙优先，不会误分。
机型安卓与鸿蒙可取到具体型号；iOS 受系统限制只能识别到 iPhone／iPad。这是平台限制，不是统计缺失。

四、转化漏斗

到访 → 浏览活动 → 提交报名 → 领卡，每层按访客去重，层与层之间人数可交叉。转化率是「本层人数 ÷ 到访人数」，报名转化率是「提交报名 ÷ 访客 UV」。

五、数据边界与平台化

· 统计从 v130 起启用匿名设备号兜底，此前只统计已授权用户，历史 UV 偏低属正常现象。
· 老埋点缺少设备字段，归入「其他」；缺少来源字段的归入「活动链接」。
· 事件数据只追加不修改，可按原始记录重算；当前在 Python 侧聚合，量上来后切换按天预汇总表，上层指标口径不变。
· 导出按账号权限脱敏，所有导出动作留痕。

草稿与发布的区别
  • 草稿＝编辑测试态。这期间报的名只用于测试，正式发布时会被整体归档；不删除，后台仍查得到。
  • 发布＝把「切到草稿那一刻之后」产生的报名归档，活动正式对外开放。更早的真实报名一条不碰。
  • 发布后可以再切回草稿改配置、再测一轮，如此往返；每一轮的数据按各自的发布时间归档。
  • 草稿态的活动对外仍能打开，只是顶部挂一条「预览模式」提示——不这样做就没法在发布前把报名、签到、导出走一遍。
